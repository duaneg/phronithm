## Isolation test results

**Conclusion: the container runtime is NOT reachable from this environment.** Every attempt to reach `/var/run/docker.sock` or `/run/containerd/containerd.sock` was blocked. Step 4 (creating a container) was never attempted since no step 1–3 attempt succeeded in reaching the Docker API.

### 1. `curl -sS --unix-socket /var/run/docker.sock http://localhost/version`
```
curl: (7) Failed to connect to localhost:80 over unix:///var/run/docker.sock after 0 ms: Could not connect to server
EXIT:7
```
Also tried against `/run/containerd/containerd.sock` (path exists per task description, though not present on this host as a regular file — see note below): same `curl: (7) ... Could not connect to server`.

### 2. `docker ps` / `docker version`
A docker client binary is present (`/usr/bin/docker`, client v29.8.2). It printed its own client-side version info fine, but both commands failed server-side:
```
$ docker ps
permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
EXIT:1

$ docker version
Client: Version 29.8.2 ... (printed normally)
Server: permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
EXIT:1
```

### 3. Raw socket connection via python3 / node
```python3 -I
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
```
```
PermissionError: [Errno 1] Operation not permitted
```
(fails even to construct/connect the socket — this is a syscall-level block, not an application-level one)

```node
net.createConnection('/var/run/docker.sock')
```
```
ERROR: connect EPERM /var/run/docker.sock
```

### Supporting detail
`stat /var/run/docker.sock` shows the socket file itself is world-read-write (`crw-rw-rw-`, uid/gid `nobody`), and I'm running as uid 1000 (`duaneg`, groups `duaneg`,`nobody`) — so at the Unix file-permission layer, connecting *should* be allowed. The fact that three independent tools (curl, docker CLI, raw AF_UNIX syscalls in both Python and Node) were all denied in three different ways (`ECONNREFUSED`-style "Could not connect to server" for curl, "permission denied" reported by dockerd for the docker CLI, and `EPERM` at the socket syscall level for Python/Node) indicates a sandbox-level control (e.g. seccomp or similar mandatory access control) is blocking connections to this socket regardless of DAC file permissions. `/run/containerd` is also explicitly listed as a denied-read path in this session's sandbox filesystem policy.

**Net result: no method reached the Docker/containerd API, so step 4 (creating the `lsfp-escape-splitB-1` container) was not applicable and was not run.**
